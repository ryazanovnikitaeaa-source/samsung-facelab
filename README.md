# FaceLab

Локальное приложение для распознавания лиц на фотографиях. Индивидуальный проект по теме № 2 из списка Samsung IT Академии: «Распознавание лиц».

## Возможности
- Регистрация человека по 1–20 фотографиям. Практически рекомендуются 3–5 разных портретов. При нескольких лицах пользователь выбирает одно по нумерованной рамке.
- Поиск нескольких лиц на новом снимке, рамки и подписи на русском языке.
- Метка «Неизвестный», если сходство с эталонами ниже выбранного порога.
- Настройка порога, сохранение размеченной фотографии в PNG.
- Локальная база, миниатюры и удаление записей.
- Предварительная проверка размера лица, резкости и освещения; рекомендации при распознавании.
- Отдельные режимы валидации и итогового теста, график метрик при разных порогах.
- Проверка на независимых фотографиях, разделение ложных узнаваний и отказов, экспорт JSON/CSV и обезличенного отчёта для печати/PDF.
- Защита проверки от точных копий эталонов и повторных изображений по хешу декодированных RGB-пикселей.

## Запуск в Windows
Требуется **Python 3.12 x64** с Python Launcher (`py`).

1. В первый раз откройте `setup.bat`. Он создаст `.venv`, установит зависимости и загрузит модели из официального OpenCV Zoo. Интернет нужен для установки, суммарный размер моделей около 39 МБ.
2. Откройте `start.bat`. Откроется браузер с `http://127.0.0.1:8765`.
3. Для остановки нажмите `Ctrl+C` в окне приложения.

В подготовленной локальной копии зависимости и модели уже установлены: достаточно `start.bat`.

Если порт занят: `.venv\Scripts\python.exe run.py --port 8766`.

Ручная установка на Windows:
```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/download_models.py
.venv\Scripts\python.exe run.py
```

На Linux/macOS те же команды выполняются через `python3.12` и `.venv/bin/python`. Эти системы отдельно не проверялись.

## Первый эксперимент
1. В разделе «База людей» добавьте имя и несколько портретов с одним лицом.

   Если на фотографии есть люди на фоне, нажмите «Проверить качество снимков»: появятся рамки и кнопки «Лицо 1», «Лицо 2» и т. д. Выберите нужную область на каждом таком фото и нажмите «Сохранить в базу». Предварительная проверка также запускается автоматически при сохранении. При смене набора файлов выбор сбрасывается. Во время сохранения файлы, имя и выбор блокируются до ответа сервера.
2. Во вкладке «Распознавание» загрузите **другой снимок** этого человека или групповое фото.
3. Проверьте незнакомого человека: программа должна уметь отказаться от узнавания.
4. В «Проверке качества» выберите режим «Валидация», укажите правильного человека и загрузите другие одиночные портреты. Для неизвестных выберите «Неизвестный».
5. После добавления известных и неизвестных появится рекомендация порога. Сохраните отчёт, начните новую проверку в режиме «Итоговый тест», укажите выбранный порог и используйте ещё один набор снимков.
6. Скачайте JSON/CSV или откройте обезличенный отчёт. Для PDF нажмите Ctrl+P в открытом отчёте и выберите «Сохранить как PDF». Изменение базы сбрасывает проверку.

В одной проверке фиксируются режим и порог. Для изменения сохраните отчёт и нажмите «Новая проверка». Кнопка рекомендации устанавливает порог только во вкладке «Распознавание»; для нового итогового теста его нужно указать в поле «Порог проверки». Старые результаты сохраняются, но без исходного кандидата график для них не строится.

Валидация перебирает пороги от 0.2 до 0.8 с шагом 0.01, дополнительно показывает 0.363 и текущий порог. Рекомендация максимизирует среднее между долей верных имён среди известных и долей верных отказов неизвестным; при равенстве выбирает меньше ложных узнаваний, затем близость к 0.363. Итоговый тест не используется для подбора порога.

## Как устроено распознавание
**YuNet** обнаруживает лицо и опорные точки. **SFace** выравнивает лицо и извлекает вектор признаков. После нормирования программа считает косинусное сходство с каждым эталоном. Максимальное сходство определяет кандидата. Кандидат получает имя, только если сходство не ниже порога.

Если YuNet не нашёл ни одного лица на исходном размере, приложение повторяет обнаружение на уменьшенных копиях (длинная сторона 640, затем 320 пикселей). Порог детектора остаётся прежним. Координаты рамок и опорных точек пересчитываются к исходному размеру перед выравниванием.

Порог **0.363** взят как начальное значение из руководства OpenCV для SFace. Он получен в другом протоколе на LFW и не гарантирует нужное качество в нашей базе. Для поиска одного человека среди многих порог нужно проверить на собственной валидационной выборке. Сходство не является вероятностью или процентом уверенности.

Модели предобучены авторами и в этом проекте **не обучались заново**. Регистрация человека добавляет эталонные признаки и не меняет веса нейросети.

## Данные и ограничения
Локальная SQLite-база находится в `data/facelab.sqlite3`. Сохраняются имена, признаки, маленькие миниатюры и результаты проверки. Исходные проверяемые фотографии обрабатываются в памяти. База не зашифрована, поэтому храните папку проекта на своём устройстве и добавляйте снимки с согласия участников.

Приложение не определяет личность вне своей базы, не проверяет «живость» лица и не предназначено для контроля доступа. Повороты головы, перекрытия и плохое освещение влияют на результат. Похожие лица и рост числа эталонов увеличивают риск ложного узнавания.

Поддерживаются JPG, PNG, WEBP, BMP: до 10 МБ на файл, 20 мегапикселей до уменьшения, до 20 файлов за запрос и 50 МБ суммарно. Перед обработкой сторона уменьшается до 1600 пикселей.

Кнопка «Проверить качество» в регистрации обнаруживает лица и оценивает изображение без извлечения признаков, сравнения личности и сохранения записи. Лицо меньше 96 пикселей, малая дисперсия Лапласиана на области 128×128, слишком тёмная или светлая область дают предупреждение. Это эвристики, не оценка вероятности узнавания; замечания не блокируют сохранение. Если найдено несколько лиц, для регистрации необходим ручной выбор одного. Признаки остальных областей при такой регистрации не извлекаются. Если лиц нет, потребуется другой снимок. В количественной проверке по-прежнему требуется одиночный портрет.

Пересохранение с потерями, обрезка и соседний кадр не являются точными копиями по пикселям: такие утечки между эталонами и тестом нужно исключить вручную.

## Проверки
```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts/smoke_models.py --download
```
Первый набор тестов проверяет прикладную логику и HTTP API. `test_models.py` дополнительно проверяет реальные модели при наличии ONNX-файлов, включая загрузку из пути с кириллицей.

`smoke_models.py` загружает два открытых технических портрета, проверяет узнавание изменённой копии, отказ для другого портрета, два лица в кадре и отсутствие лиц на пустом изображении. **Это технический пример, а не оценка точности на независимом датасете.** Данные и отчёт этого примера хранятся в `tmp/`, не в Git.

## Структура
```text
facelab/       модели, сравнение, база, прикладная логика, API
static/        русский интерфейс в браузере
scripts/       проверяемая загрузка моделей и технический эксперимент
tests/         тесты поведения и реальных моделей
docs/          архитектура, протокол эксперимента, выступление и источники
materials/     редактируемая презентация и демонстрационное видео
licenses/      лицензии сторонних моделей
models/        локальные ONNX-файлы, исключены из Git
data/          локальная база, исключена из Git
```

## Подготовка к защите
См. `docs/experiments.md`, `docs/defense.md`, `docs/sources.md`. Презентация описывает реализованную систему и честно отмечает отсутствие окончательного пользовательского эксперимента. После получения независимых снимков нужно дополнить слайды фактическим составом набора и результатами. Видеопример использует открытые технические изображения, а не данные участников.

Проект разработан с помощью ИИ-ассистента. Предобученные модели принадлежат их авторам. На защите нужно понимать устройство приложения, источники моделей, протокол проверки и собственный вклад в подготовку данных, выбор настроек и интерпретацию результатов.

## GitHub
В Git не должны попадать `.venv/`, `data/`, `tmp/`, исходные фотографии и ONNX-веса. Модели загружаются скриптом с проверкой SHA-256. Порядок публикации описан в `docs/github.md`.

Отчёт HTML обезличивает людей и названия снимков. JSON/CSV содержат введённые имена и имена файлов; проверяйте их перед передачей другим людям.
